Hauhau Qwen3.5 27B: Gufo setup

Publisher repository · Q4_K_M · Gufo 0.20 · 262,144 total tokens configured · one session · text-only. Input, tools, reasoning and output share the context budget; 32,768 output tokens are reserved by the server configuration.

Daily use

pi-hauhau
# Or:
hermes-hauhau
# Stop the active engine:
localai stop

Run either harness from your project directory. It starts Gufo automatically. ComfyUI can run alongside Gufo, with a shared-memory warning. To switch inference models, finish active work and run localai stop first. Existing plain Pi/Hermes and Gufo Flash launchers are unchanged.

Compatibility workaround

The untouched publisher GGUF does not load directly in this pinned Gufo runtime: its chat-template hash is unrecognized. The publisher’s F16 vision projector is also rejected by Gufo’s BF16 vision loader. This profile therefore uses a separate GGUF with only its chat-template metadata replaced by the already-installed, Gufo-supported Unsloth Qwen template. The publisher model and projector remain intact. Every model tensor is compared by SHA-256 before the copy is registered. Vision is disabled for this Gufo profile; the F16 projector remains available to compatible engines. This is a documented compatibility adaptation, not native publisher-template support.

Steps taken, and how to recreate them

  1. Registered the repository in catalog.json as qwen35-hauhau-q4, pinned to revision ba23816347e0f24d82efbd2397278ff32743b75c. Selected only the Q4_K_M weights and matching F16 projector; verified their publisher SHA-256 hashes.
  2. Created the separate compatibility GGUF with prepare_hauhau.py. It extracts the supported template from the existing qwen27-q4 model, checks its pinned hash, uses the installed GGUF metadata tool and verifies that all non-template metadata and model tensors are unchanged.
  3. Added gufo-hauhau to profiles.json: pinned official Gufo runtime, one session, 262144 context, 26 GiB RAM-cache budget, 40 GiB disk-cache budget and 16 GiB disk staging with an 8 GiB minimum free-memory reserve. Target-only generation; no draft from another model. Thinking enabled; temperature 0.6, top-p 0.95, top-k 20, min-p 0. Long-context acceptance has not been measured.
  4. Merged the new Pi model registration, created its separate Hermes configuration, and installed two global launchers with register_profile.py. It preserves existing defaults and backs up edited registry/launcher files under ~/.local/state/localai/profile-registration/.

With this repository’s current configuration, existing shared tooling, pinned Gufo image and qwen27-q4 reference model installed, recreate the setup with:

cd /home/danfl/dev/LocalAi
localai download qwen35-hauhau-q4
~/.local/share/localai/apps/support/bin/python scripts/linux/prepare_hauhau.py
~/.local/share/localai/apps/support/bin/python scripts/linux/register_profile.py gufo-hauhau --suffix hauhau
pi-hauhau

To run the engine alone: localai start gufo-hauhau. Its OpenAI-compatible API is http://127.0.0.1:8080/v1, model ID gufo-hauhau. Use localai serve gufo-hauhau for a foreground server with Ctrl-C.
